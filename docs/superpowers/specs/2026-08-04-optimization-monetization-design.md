# 鉴来助手 — 优化与变现方案设计文档

**日期**: 2026-08-04
**状态**: ✅ 已确认
**项目**: 鉴来助手（Novel Copilot），Chrome 扩展 + FastAPI 后端

---

## 背景与约束

当前状态：
- Chrome Web Store + Edge Store + Greasy Fork 已上线
- 后端 FastAPI + SQLite + DeepSeek v4 Flash API
- 免登录试用 3 次，注册送 10 次，每日签到 +8 次
- 支付功能暂未开放（个体户执照未办理）
- 无用户行为统计数据
- 官网 jianla.xyz 已备案

核心约束：
1. **无支付体系** — 个体户执照未办，微信支付未接入
2. **无数据** — 不知道用户量、使用频率、转化率
3. **成本压力** — DeepSeek API 每次调用都花钱，无缓存共享
4. **稳步推进** — 不打闪电战，一步步来

## 阶段一：筑基（Week 1-2）

### 1.1 数据统计

**目标**：零数据的现状必须打破。加埋点，建仪表盘。

**需要的指标**：

| 指标 | 数据来源 | 用途 |
|------|---------|------|
| DAU / WAU | usage_logs 表按日聚合 | 判断用户规模 |
| 每日分析次数 | usage_logs 按 action=analyze | 算 AI 成本 |
| 免登录→注册转化率 | guests vs registrations | 判断试用策略效果 |
| 功能使用分布 | analyze / ask / report / review 占比 | 指导功能优先级 |
| 错误率 | error 记录 vs 总请求 | 找稳定性问题 |
| 平台分布 | 扩展 source_url pattern | 知道主战场在哪 |
| 用户留存 | 注册后 D1/D7/D30 活跃比例 | 判断产品粘性 |

**实现**：
- 后端新增 `/api/admin/stats` 聚合 API
- 管理后台新增仪表盘 HTML 页面，用 Chart.js 可视化
- 扩展 content.js 新增静默安装上报（POST `/api/track` 扩展字段）

### 1.2 降 AI 成本

**当前问题**：分析缓存以 `(username, text_hash, detail_level, spoiler_free)` 为主键，每个用户都要独立调一次 AI。

**优化措施**：

| 优化 | 改动 | 预期省成本 |
|------|------|-----------|
| **全局分析缓存** | analyses 表去掉 username 约束 | 热门书 50%+ 重复调用消除 |
| **摘要结果缓存表** | 新建 `summary_cache` 表，存 (text_hash, summary) | 渐进式分析的首段摘要不再重复 |
| **提示词瘦身** | ai_service.py 中 prompt 精简格式说明 | 每次省 ~200 token |
| **问答缓存持久化** | 当前仅内存 qa_cache，重启丢；加 SQLite 表 | 重启不丢，命中率提升 |
| **前端文本提纯** | content.js 章节提取去广告/去导航更精准 | 每次省 500-1000 token |

**最重要的一项**：
```
-- 当前（每人独立缓存）
UNIQUE(username, text_hash, detail_level, spoiler_free)

-- 改为（全局共享缓存）
UNIQUE(text_hash, detail_level, spoiler_free)
-- 然后用 INSERT OR IGNORE，已有结果直接返回
```

**注意**：全局缓存需要确认隐私没问题——不存 username 意味着缓存结果不包含个人数据，OK。

### 1.3 体验修复

优先级排序（影响最大 → 最小）：

1. **分析历史回看入口**（P0）
   - 弹窗中加一个"最近分析"列表，点进去看之前的分析结果
   - 数据已经存在 `analyses` 表，纯前端改 popup.html/popup.js

2. **首次使用引导**（P0）
   - 首次打开弹窗显示 3 步引导：点扩展图标 → 打开小说章节 → 点分析
   - 用 `chrome.storage.local` 记"是否已完成引导"

3. **手机端 Alook/Via 样式修复**（P1）
   - 油猴手机版的 vis-network 关系图在小屏幕上溢出
   - 加 responsive 样式和触摸手势

4. **FAQ / 帮助页**（P1）
   - 官网加一个 FAQ 区块或在弹窗里加帮助入口
   - 覆盖：怎么用、支持哪些平台、额度怎么获取

5. **官网加演示截图/GIF**（P2）
   - 录一个 30 秒的功能演示 GIF
   - 放官网 Hero 区，直观展示产品

## 阶段二：蓄客推广（Week 2-4，持续进行）

### 2.1 推广前检查清单

- [ ] 官网有产品截图/GIF
- [ ] 首次使用有引导
- [ ] 错误兜底可靠（AI 超时不崩）
- [ ] 服务器能扛住峰值（Nginx worker_connections 够用）

### 2.2 渠道矩阵

| 渠道 | 内容类型 | 频率 | 目标 |
|------|---------|------|------|
| 小红书 | 种草图文 | 周 1-2 篇 | 触达网文读者 |
| 贴吧（起点吧/书荒吧） | 自然回复 | 日 2-3 条 | 精准获客 |
| 知乎 | 长回答 | 周 1-2 篇 | 长尾 SEO |
| 抖音 | vibecoding 风格演示 | 周 1-2 条 | 破圈 |
| B站 | 使用教程 | 1-2 条打底 | 信任建设 |
| Greasy Fork | 已上架，被动流量 | 0 | 自动 |

### 2.3 核心宣传话术

**主痛点**：
- "隔几天再看，前面讲了什么全忘了"
- "人物太多、关系太乱，谁跟谁什么关系记不住"

**一句话介绍**：
> 鉴来助手 — AI 自动追踪伏笔、生成人物关系图，追更不迷路

### 2.4 用户群

- QQ 群挂在插件弹窗和官网
- 初期群主亲自回答问题和收集反馈
- 反馈 → 优化需求 → 迭代

### 2.5 赞赏码过渡

- 在弹窗底部和官网放微信赞赏码
- 用户赞赏后联系管理员手动加额度
- **核心目的不是收入，是验证"付费意愿"这个假设**

## 阶段三：变现（Week 4+）

### 3.1 前置条件

阶段三启动前提：前两阶段跑出的数据满足以下条件任意一条：
- 日活稳定在 50+
- 有用户主动问"怎么付费/额度不够用"
- 赞赏码收到过钱（哪怕只有一次）

**如果不满足** → 继续阶段二推广，先不急着变现。

### 3.2 定价方案（待数据验证后调整）

```
尝鲜包（50次）   ¥4.9   → 适合轻度用户
实惠包（200次）  ¥12.9  → 主力套餐
畅读包（500次）  ¥24.9  → 重度用户
月卡（30天无限） ¥19.8  → 追更党
```

### 3.3 支付接入路径

```
挂赞赏码（过渡期）
    ↓ 验证付费意愿
办理个体户营业执照（广东政务服务网，免费）
    ↓ 1-2 周
申请微信支付商户号
    ↓ 1-2 周
main.py 接入支付回调
    ↓ 1-2 天
正式上线套餐
```

## 不做的

以下事项主动排除，避免分散精力：
- ❌ 不做多语言/国际化
- ❌ 不做 App（先做好浏览器端）
- ❌ 不做 AI 模型切换（DeepSeek 性价比最优）
- ❌ 不做复杂的付费前引导（免登录 3 次 + 签到 8 次够了）
- ❌ 不做冷启动广告投放（先靠内容自然增长）

---

## 风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| DeepSeek API 涨价或不可用 | 低 | 预留了 prompt 瘦身和缓存优化余地；可切通义千问/智谱 |
| 推广效果差、用户不增长 | 中 | 数据仪表盘会揭示留存率——如果留存好只是曝光不够就加大推广；留存差就说明产品有问题先修 |
| 没有人愿意付费 | 中 | 赞赏码阶段就能验证，零损失。如果没人付，继续免费路线攒用户量 |
| 微信支付接入被拒 | 低 | 小说阅读工具属于正规软件，风险低 |
